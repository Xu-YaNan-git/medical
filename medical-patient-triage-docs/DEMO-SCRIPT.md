## 0. 演示前准备（提前 10 分钟，观众不看）
1. 健康检查，两端都应 `status:ok`，`guardrails.packageLoaded=true, version=0.2.0`：
   ```bash
   curl -s http://127.0.0.1:8001/health; echo
   curl -s http://127.0.0.1:8000/health; echo
   ```
   不通：`/workspace/medical-start-all.sh` 拉起本机四端。
2. 重置演示数据（两端）：
   ```bash
   curl -s -XPOST http://127.0.0.1:8001/api/demo/reset
   TK=$(curl -s -XPOST http://127.0.0.1:8000/api/auth/login -H 'Content-Type: application/json' \
        -d '{"username":"doctor","password":"demo123"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")
   curl -s -XPOST http://127.0.0.1:8000/api/demo/reset -H "Authorization: Bearer $TK"
   ```
   期望 `{"ok":true,"seedVersion":"m9-golden-1",...}`。也可在 UI 点「重置演示数据」。
   注意：reset 会把运营看板「护栏拦截」计数清零，第 2 步之后才会出现数字。
3. 两个浏览器窗口分别打开 8765、36967，**各硬刷新一次**（Ctrl+Shift+R / Cmd+Shift+R），Service Worker 缓存名应为 `triage-shell-v16-guardrail-020`。
4. 预热模型：在患者端先做一次普通导诊（首调最慢），再 reset 一次患者端。
5. 浏览器缩放 110–125%，关闭通知；患者端可用手机尺寸（DevTools 设备模式）更像 App。

## 1. 患者导诊（普通症状）· 75s
- **操作**：患者端首页 → 「症状导诊」（导诊台）→ 主诉框（占位「例如：咳嗽伴低热三天，或胸痛、呼吸困难…」）输入 **咳嗽发热**，持续时间 2 天、程度中等（或直接点「普通示例（咳嗽）」）→ 点 **「生成导诊建议」**。
- **期望画面**：按钮变「AI 思考中…」约 8–13 秒 → 导诊结果：**呼吸内科**排第一、全科医学次之，紧急程度为常规，附推荐理由和免责声明。
- **旁白**：「患者不知道挂哪个科，这是医院最常见的问题。用一句大白话描述，AI 给出推荐科室和理由。」等待时补一句：「这里是真模型在推理，大概十秒。」
- **兜底**：
  - 超过 15 秒：「真实大模型在线推理，正式部署会用院内专线和缓存。」最长 60 秒超时后自动回退。
  - 结果标为 Mock / 规则来源（上游 503 或无 key）：「这台演示机断网也能跑，走的是本地规则兜底，链路完全一样。」继续演示，不要重试。

## 2. 红旗「胸口剧痛」急诊卡片 · 45s
- **操作**：返回导诊台，主诉输入 **胸口剧痛** → 「生成导诊建议」。
- **期望画面**：几乎瞬时（护栏短路、不调模型）弹出红色急诊卡片「建议立即急诊」，内容「立即急诊/拨打120」，按钮 **「拨打120」**、**「我知道了」**；结果页 nextSteps 以列表展示，推荐心内科。
- **旁白**：「危险症状不会交给 AI 自由发挥。安全护栏先拦截，直接引导急诊，不让患者在 App 里排队。」
- **兜底**：
  - 弹窗位置：居中覆盖层；没看到先往下滚或看结果页顶部红色区。点「我知道了」只关闭卡片。
  - 不要点「拨打120」（手机模式会真拨号）。
  - 若未弹：硬刷新后重试一次；仍不弹，展示截图 `/workspace/s2-shots/v16-p-redflag-modal.png`。
  - 可选加分（+15s）：输入「有点胸闷」→ 只出琥珀色小提示（疑似急症，不弹窗，不锁输入）。开着模型复判时也可能升为急诊卡片，按「宁可多提示」口径属预期。

## 3. 预约挂号 · 50s
- **操作**：回到第 1 步的普通结果（或重新导诊「咳嗽发热」）→ 点 **「一键去预约」**（或「预约该科室」）→ 选一个日期/号源 → **「确认预约」** → 「查看我的预约」。
- **期望画面**：预约成功，「我的预约」中出现该号源，状态「已预约」。
- **旁白**：「导诊结果直接带着科室跳到预约，一步挂号，不用再找科室。」
- **兜底**：号源为空 → 前一晚未 reset，执行第 0 步 reset 后刷新；或从底部导航「预约」→「预约挂号」手动选呼吸内科。

## 4. 医生工作台 · 预问诊 · 60s
- **操作**：切到医生端窗口 → 用户名 doctor / 密码 demo123 → **「登 录」** → 「医生工作台」→ 「就诊列表」点 **v1 王小明** →「接诊」/打开详情。
- **期望画面**：右侧「预问诊 · AI 辅助 / 患者预问诊报告」已显示 pcr-seed-1：主诉「反复上腹痛 3 天」及摘要；可点「采纳主诉」「采纳现病史/摘要」写进病历框。
- **旁白**：「患者来之前在手机上做过 AI 预问诊，医生打开就能看到整理好的摘要，一键采纳，省掉重复问诊。」
- **兜底**：
  - 显示「未关联预问诊」+ 选择器：说明打开的不是 v1（或未 reset）；在选择器选 pcr-seed-1 →「关联」。
  - 「预问诊加载失败」：8001 不通，改讲截图 `v16-d-pc-v1-linked.png`。

## 5. 鉴别诊断 · 60s
- **操作**：病历框已有主诉/现病史（不够可点「填入示例病情」）→ 点 **「生成鉴别诊断」**。
- **期望画面**：按钮「AI 思考中…」并禁用约 10 秒 → 「鉴别诊断」列表（约 4 条，含可能性与依据），每条可「采纳」/「排除」，可「写入病历诊断」；下方检查/用药建议，可「基于已采纳诊断刷新建议」「一键写入医嘱」。
- **旁白**：「AI 只给参考，决定权在医生：逐条采纳或排除，采纳的才进病历。」
- **兜底**：慢 → 「医生端同样是真模型，约 10 秒」；Mock/降级（llm_fallback）→ 「这是降级的通用示例，结构一致，正式环境接院内模型」。不要连点（按钮已防连点）。

## 6. 一键病历 · 50s
- **操作**：点 **「一键生成可编辑病历」** → 可试「更规范润色」→「复制 Markdown」/「导出病历（Markdown）」。
- **期望画面**：约 10–13 秒后生成结构化病历（主诉、现病史、诊断、医嘱），全部可编辑，带 AI 免责标注。
- **旁白**：「写病历是医生最耗时的事。现在一键出初稿，医生改两处就能签字。」
- **兜底**：同第 5 步；超时 60 秒后回退，旁白不停，展示 `v16-d-ai-done.png`。

## 7. 运营看板 · 护栏拦截 · 40s
- **操作**：医生端顶部 **「运营」/「运营看板」** → 找 **「🛡 护栏拦截」** 卡片。
- **期望画面**：今日预约、待接诊等卡片；护栏拦截卡片按类别（如 redflag_cardiac）、动作（redflag/refuse）、患者端/医生端分开统计；刚才的胸口剧痛已计入（reset 后至少 1）。
- **旁白**：「每一次拦截都有记录可审计，院方能看到 AI 在哪里被拦、拦了什么。」
- **兜底**：卡片标「Mock」= 8000 访问不到患者端汇总，说明「演示机网络问题，数字为示例」；计数为 0 = 第 2 步未执行或刚 reset。

## FAQ
**Q：数据是真的吗？** 全部是演示种子（m9-golden-1），页面标「演示链路，非真实就医」；不含真实患者信息。截图均来自实机页面，没有编造数字。

**Q：合规怎么做？** AI 输出均带免责声明，只做导诊和辅助参考，不开处方、不替代医生；越权请求（开处方、具体剂量、套取系统提示）拒答；输出层做合规检查，手机号等敏感信息脱敏，审计日志不存明文。

**Q：护栏效果多少？** 在一批**没参与调规则**的新说法（holdout）上，规则+模型复判：危险症状识别 **96.4%**（27/28），越权拒绝 **96.3%**（26/27）；调规则用的测试集全部满分。自动化冒烟 **69 条全过**（真模型、纯规则、Docker compose 三轮）。

**Q：模型挂了怎么办？** 超时/503 自动回退规则或 Mock，红旗检测不依赖模型，仍会拦截。

**Q：多快？** 真模型单次约 8–13 秒；红旗拦截毫秒级。

**Q：能接医院系统吗？** 下一步计划：账号与多角色、对接 HIS、找试点医院。
